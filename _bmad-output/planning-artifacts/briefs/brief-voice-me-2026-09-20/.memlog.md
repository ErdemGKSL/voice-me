- (decision by user) Core concept: desktop app 'voice-me' - in-game hotkey opens a small prompt UI, user types text, on Enter the UI closes and the text is spoken aloud in the user's own cloned voice via a virtual microphone device that other apps (games, Discord, Zoom) can select as input
- (decision by user) TTS engine: Chatterbox-Multilingual V3 (voice cloning via reference audio + text + language_id), MIT licensed, ~23-25 languages
- (decision by user) UI framework: GPUI (Rust, Zed's framework); app ships as a single executable (direct .exe on Windows etc.), no traditional installer
- (decision by user) Target platforms: Windows, macOS, Linux - all three
- (decision by user) UI language support: Turkish and English only; spoken output language can be broader (whatever Chatterbox language_id supports)
- (decision by user) Voice data: user provides their own voice as the reference audio (recorded in-app)
- (decision by user) Project type: personal hobby project, free and open source
- (decision by user) Inference: local-only, no cloud/hybrid option
- (decision by user) Dependency handling: no setup-time requirements page; missing dependencies (Python/CUDA/etc.) are detected and surfaced inside the app UI, with one-click auto-install where feasible
- (insight) Research: Chatterbox has no official ONNX/Rust binding; bundling into a native exe likely requires embedding a Python runtime (PyOxidizer/python-build-standalone) or subprocess to a bundled Python - real packaging risk
- (insight) Research: virtual mic creation differs sharply by OS - Windows needs a signed kernel/WDM driver (VB-Cable model, EV cert + WHQL), macOS needs a notarized CoreAudio HAL plugin/driver extension (BlackHole model) with user approval, Linux can use a PipeWire/PulseAudio null-sink with no driver at all. 'Single executable' claim is in tension with Windows/macOS both needing a separate signed driver/extension
- (insight) Research: GPUI is pre-1.0, Windows port lagging, no built-in system tray or global hotkey support upstream (a community fork 'Adabraka GPUI' adds these); no native Python interop, needs FFI/subprocess for ML inference
- (insight) Research: no existing tool found doing exactly 'type text -> own cloned voice -> virtual mic, for gaming' - closest are Voicemod/Voice.ai (live voice change, not typed-text TTS) and VoxBooster (claims driverless virtual mic + local voice cloning) - differentiation room exists but no proven reference architecture
